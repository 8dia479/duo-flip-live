# Flip 6 실기기 진단 절차 — NOT TESTED ON DEVICE

이 빌드는 시스템 화면 전환 포팅이 아니다. 미리보기는 합성 이미지만 렌더링하고 앱 외부 화면을 캡처하지 않는다. SM-F741에서 Fold 배경화면 프로필과 주요 Fold 애니메이션 경로는 차단되어 있다. 실기기에서 One UI가 정상 동작한다고 아직 검증하지 않았다.

## 설치 전

GitHub Actions의 `flip-preview-debug-apk` 아티팩트에는 디버그 APK, SHA256SUMS, 패키지 정보, APK 목록 및 서명 검사 결과가 포함된다. SHA-256을 검증하고 `package-info.txt`에서 패키지명·SDK를 확인한다. 기존 앱과 패키지명은 같지만 디버그 서명은 공식 릴리스와 다르므로 업데이트가 거부될 수 있다. 기존 앱을 제거하면 설정과 앱 데이터가 삭제될 수 있으니 백업 없이 제거하지 않는다. 알 수 없는 출처 앱 허용 여부는 사용자가 결정한다.

## 데이터 수집

1. 앱 초기 설정 화면 또는 메인 화면의 **Experimental Flip preview**를 연다. 이 단계에서 삼성 배경화면을 적용하거나 Shizuku 권한을 허용할 필요는 없다.
2. 수동 모드에서 180 → 90 → 0 → 90 → 180을 천천히 이동하고, 중간 정지·빠른 이동·방향 반전을 확인한다. 가상 값은 물리 센서의 증거가 아니다. 효과 방향 선택과 감도/노이즈 deadband를 시험한다.
3. **Public sensor**를 선택해 센서 이름, 원시 각도, 이벤트 시간과 정확도 표시를 확인한다. **Record sensor**를 누른 후 여러 속도로 접고 펼친다. 원시 이벤트 CSV와 디스플레이 이벤트 CSV를 각각 복사한다. 기록은 앱이 전면에 있을 때만 수행되며 최대 512개 센서 이벤트와 32개 디스플레이 이벤트를 메모리에 보관한다. 화면을 벗어나면 기록이 중단되므로 전환 구간 전체가 수집되었다고 가정하지 않는다.
4. 0/90/180만 나왔다면 단계형 관측값으로 기록한다. 다양한 값은 관측 증거일 뿐, 모든 자세에서 연속 입력이 보장된다는 뜻이 아니다. 이벤트가 없으면 정지한 on-change 센서와 끊어진 센서를 구별할 수 없다. 로그를 공유하기 전에 내용을 검토한다.
5. 화면 목록의 크기·밀도·회전·상태 및 표시된 후보를 기록한다. 크기 기반 후보는 외부/가상 디스플레이를 포함할 수 있으며 물리 패널의 확정 식별이 아니다. 하나가 사라지거나 ID가 바뀌면 이를 기록한다. 표시되지 않는 커버 화면은 발견된 것으로 간주하지 않는다.
6. Shizuku 연결 상태와 삼성 FoldInteractive 컴포넌트 표시 여부를 기록한다. 컴포넌트가 보이더라도 각도 응답, 권한, 사용 가능한 배경화면 또는 시스템 제어가 입증된 것은 아니다. 실험 중 기본 삼성 화면 전환에 문제가 생기면 앱을 닫고 애니메이션을 비활성화한다.

수집 결과에는 모델명, Android/One UI 버전, 사용한 빌드/커밋, 센서 및 디스플레이 관측을 함께 기록한다. 화면 픽셀의 실제 연속성, 잠금·절전·앱 전환 및 반복 폴딩은 영상과 별도 관측이 필요하다. 다음 항목은 모두 **NOT TESTED ON DEVICE**: 힌지 연속성, 디스플레이 식별, 셰이더 시각 정확도, Shizuku 권한 및 삼성 wallpaper 응답, 커버 handoff, 프로세스 종료/복구, 배터리·성능, 실제 One UI 시스템 전환.
