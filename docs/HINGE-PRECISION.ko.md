# Galaxy Z Flip 6 힌지 센서 경로

## 현재 구현

- 기본 Android `TYPE_HINGE_ANGLE`은 보조 입력으로 유지한다. 이 값이 0°/90°/180°처럼 단계형이어도 화면에 다른 숫자를 꾸며 넣지 않는다.
- Shizuku가 실행 중이고 Duo Flip 권한이 승인된 경우, 별도의 읽기 전용 UserService가 `logcat -v epoch -T 1 -s sensors-hal:I *:S`를 실행해 삼성 힌지 센서 관련 로그만 읽는다.
- 파서는 `folding_angle`, `lid_angle_fusion`, 닫힘 Hall 상태 이벤트만 받아들인다. 관련 없는 로그는 각도 입력으로 취급하지 않는다.
- 홈/미리보기에는 실제 로그의 마지막 원시 측정값과 애니메이션용 중간 프레임 추정값을 별도로 표시한다.
- 추정기는 두 센서의 각 샘플 시각과 변화량을 바탕으로 센서 이벤트 사이의 움직임을 보간한다. 이는 광학적으로 측정된 실제 각도가 아니라 렌더링용 추정치다.
- Shizuku 또는 HAL 로그를 사용할 수 없으면 Android 공개 센서값으로 되돌아간다. 추정값을 합성하지 않는다.

## Flip 6에서 검증되지 않은 가정

참고 구현은 Galaxy Z Fold 8 Ultra에서 `folding_angle` 약 11°, `lid_angle_fusion` 약 10° 간격의 샘플을 관찰했다고 설명한다. 이 간격은 Flip 6에서 확인된 사양이 아니다. 따라서 현재 보간기의 10°/11° 상한은 임시값이다. Flip 6에서 실제 로그를 수집한 뒤 두 채널의 샘플 간격, 타임스탬프 기준, 역방향 전환, 정지 상태를 확인해 조정해야 한다.

센서명 목록이 기기에 존재하는 것과 로그를 읽을 수 있는 것은 서로 다르다. `com.samsung.permission.SSENSOR`를 우회하거나 권한을 탈취하지 않는다. HAL 로그가 접근 거부되면 진단 상태에 오류를 표시하고 공개 센서 입력으로 돌아간다.

## 내일 Flip 6에서 확인할 순서

1. Shizuku를 실행하고 Duo Flip 권한을 허용한다.
2. Duo Flip 홈에서 센서 상태가 `삼성 정밀 힌지 센서 로그 사용 중` 또는 연결 대기/오류 중 무엇인지 확인한다.
3. 애니메이션 미리보기에서 `실시간 센서`를 선택한다.
4. 휴대전화를 편안한 범위에서 천천히 움직이고, 화면에 표시되는 원시 측정값의 출처가 `folding_angle` 또는 `lid_angle_fusion`으로 바뀌는지 확인한다.
5. 원시값이 0/90/180뿐인지, 그 사이 값도 들어오는지 확인한다. 원시값은 계단식이어도 추정값만 부드럽게 움직일 수 있다.
6. 미리보기의 센서 기록을 복사하면 CSV에 타임스탬프, 원시각도, 출처가 저장된다. 기록에는 센서 이벤트만 포함된다.
7. HAL 로그가 계속 대기 중이면 해당 상태와 센서 목록을 알려준다. 그때는 PC에서 다음 명령을 직접 실행해 결과를 확인할 수 있다.

```sh
adb shell logcat -v epoch -T 2 -s sensors-hal:I '*:S'
```

명령 출력에 개인 정보가 섞일 수 있으므로 전체 로그를 공개 저장소에 올리지 않는다. 센서 관련 한두 줄만 확인한다.

## 시스템 화면 동작과의 구분

이 작업은 센서 입력과 앱 내부 미리보기만 수정한다. 힌지 각도가 0°로 표시되거나 HAL 닫힘 이벤트를 수신해도 One UI가 실제 화면을 끄는 동작을 앱이 제어한다는 뜻은 아니다. 시스템 디스플레이 전환은 별도 검증 전까지 비활성 상태로 둔다.
